Phase 0–1 · Feb 25, 2026
The Repository Exists
Late February · From web app to Electron desktop

Before the repository, OmniPlanner was a web-based weekly planner living inside Vite + React. The idea was simple: a week-isolated planning workspace where each week is its own page with goals, todos, habits, and calendar blocks.

Then it became an Electron desktop app.

The conversion was messy but fast. Tauri was considered. Electron won for speed of iteration. The first commits added electron-main.cjs, preload.cjs, run.js launcher, and a package.json with electron-builder config targeting Windows NSIS, macOS DMG, and Linux AppImage.

This is where omniplan-ai---executive-life-os/ became the app directory and the project stopped being a disposable web experiment.

The first AI provider (Gemini) was wired in the same day. Dead code was removed. The first GitHub Actions CI workflow built executables automatically.

Phase 2–3 · Feb 26 – Mar 18, 2026
Life Goals Go Domain
Late February · GoalItem migration and week-isolated architecture

The core data model was taking shape. Week-isolated planning — the idea that each week is an indestructible page that doesn't bleed into adjacent weeks — was the architectural bet.

Phase 2 introduced the GoalItem domain model: structured life goals (10-year, 5-year, 3-year, 1-year, monthly, weekly) that link to weekly execution via Todo.parentGoalId. The LifeGoals text blobs were migrated into typed GoalItem[] records.

Phase 3 connected goals to weeks. Weekly goals (business and personal) could now link upward to life goals. The weekly planner sidebar showed relevant 1-year goals for the current week.

Phase 4 hardened credentials: services/storage/secureSettings.ts became the single boundary for sensitive keys. Electron.safeStorage encrypted API keys and IMAP passwords in credentials.enc.json.

Domain Model Goal Linking Credential Encryption v2.0

Calendar Intelligence, Web Shell, and Mobile

Current · May 2026
Dashboard, Alarms, and the Plan-vs-Actual Gap
May 2026 · Redesigning the main screen

The weekly planner was solid. The habits worked. The calendar connected to email. But the main screen was still a weekly grid — and nobody opens a planner to see a grid. They open it to know what's next.

So the main screen is now a Dashboard: today's top events ranked by priority × urgency, habits due now, recent emails, and top todos. Every event card has a Start button. Tap it when the event begins. Tap Skip when you miss it. Tap Snooze when you need 5 more minutes.

Sleep events get a special "Going to bed" button. The alarm rules engine auto-generates wind-down alarms (60 min before sleep) and wake alarms (8 hours later) from sleep events.

A new Pulse tab manages all alarms and reminders. Morning planner, habit check-in, focus block alerts — each with a toggle. Event-derived alarms show upcoming auto-generated nudges.

The plan-vs-actual overlay on the weekly grid is next: soft translucent blocks for what you planned, solid opaque blocks for what actually happened, with a per-day toggle.
